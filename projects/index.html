PROJECT 1
Customer Churn Prediction Using Artificial Neural Network
This project develops an Artificial Neural Network (ANN) to predict whether a telecom customer is likely to churn or remain with the service. The project uses customer demographic, service, account and payment information, followed by data preprocessing, model development and performance evaluation using classification metrics.
+
1. Project Objective & Dataset +
  • The objective of the project is to predict whether a telecom customer is likely to churn or stay.
  • The project uses the Telco Customer Churn Dataset.
  • The dataset contains 7,043 customer records with 21 original features.
  • Customer information includes demographic, account, service and payment-related details.
  • The target variable is Churn, indicating whether the customer left the service.
2. Data Preprocessing & Analysis +
  • Unnecessary customer identification information is removed.
  • Missing and inconsistent values are handled.
  • Categorical variables are converted into numerical form.
  • Yes/No variables are encoded as numerical values and multi-category variables are one-hot encoded.
  • Numerical features are scaled before training the neural network.
  • Exploratory analysis is performed to study customer churn and important customer attributes.
3. ANN Model Development +
  • The processed customer data is used to develop an Artificial Neural Network (ANN).
  • The network uses 26 input features.
  • Hidden layers use the ReLU activation function.
  • The output layer contains one neuron with Sigmoid activation for binary classification.
  • Adam is used as the optimizer.
  • Binary Cross-Entropy is used as the loss function.
4. Model Evaluation & Comparison +
  • The ANN model is evaluated using classification performance measures.
  • Accuracy and classification report are used to evaluate the model.
  • A confusion matrix is used to analyze correct and incorrect predictions.
  • ANN performance is compared with other machine learning models.
  • The comparison includes Logistic Regression, Random Forest and Support Vector Machine (SVM).
5. Prediction for New Customers +
  • New customer data is processed using the same preprocessing procedure used during training.
  • The trained ANN predicts the probability of customer churn.
  • A probability threshold of 0.5 is used for the final churn decision.
  • Customers can therefore be classified as Churn or Not Churn.
  • The predicted results can be saved for further analysis.

PROJECT 2
Weather Prediction using Linear Regression
This project uses historical weather records from multiple stations to predict average temperature, minimum temperature, maximum temperature and rainfall. The workflow includes data preprocessing, feature preparation, Linear Regression model training, evaluation using R² and RMSE, and prediction for a selected date and station using Python.
+
1. Project Objective & Dataset +
  • The objective of the project is to develop a data-driven weather prediction system using Linear Regression.
  • The project uses a historical weather dataset containing daily records from multiple weather stations.
  • The dataset contains date-wise information including average temperature, minimum temperature, maximum temperature, and rainfall.
  • The Excel dataset used in this project is weather data set.xlsx.
  • The dataset is processed locally as part of the project; no external Kaggle link is required on this page.
2. Input & Output Variables +

Input Variables

  • year – year extracted from the date of record
  • month_num – month number derived from the date
  • day – day of the month
  • station_encoded – numerical encoding of station names

Output Variables

  • avg_temp – predicted average temperature (°C)
  • min_temp – predicted minimum temperature (°C)
  • max_temp – predicted maximum temperature (°C)
  • rainfall – predicted rainfall amount (mm)
3. Data Preprocessing +
  • The date_of_record column is converted into a date format.
  • The data is sorted chronologically.
  • Year, month and day are extracted from the date.
  • Station names are converted into numerical values using LabelEncoder.
  • Missing temperature values are handled using interpolation and remaining missing values are filled with the mean.
  • Missing rainfall values are replaced with 0.
4. Linear Regression Model Development +
  • The processed dataset is divided into input features and output variables.
  • The model uses Linear Regression from scikit-learn.
  • The prepared data is divided into training and testing subsets.
  • The model learns relationships between date/station information and the four weather outputs.
5. Model Evaluation +
  • The trained model is evaluated using the R² Score.
  • RMSE (Root Mean Square Error) is also calculated to measure prediction error.
  • Actual and predicted values can be compared to understand model performance.
  • When actual weather data is available for a selected date and station, percentage errors are also calculated.
6. Prediction for a Given Date & Station +
  • A function named predict_weather() is used to generate predictions.
  • The user provides a date and station name.
  • The date is converted into year, month and day features.
  • The station name is encoded using the trained station encoder.
  • The model predicts average temperature, minimum temperature, maximum temperature and rainfall.
  • If actual data exists for that date and station, the program also reports prediction errors.
7. Example Prediction & Insights +
  • An example prediction can be generated for a selected station and date.
  • The program displays the predicted weather values.
  • When the actual record is available, the corresponding percentage errors are displayed.
  • The model score is also displayed to provide an overall indication of model performance.

PROJECT 3
Student Pass / Fail Prediction using Logistic Regression
This project develops a Logistic Regression model to predict whether a student is likely to pass or fail based on academic performance and demographic attributes. The project uses study hours, attendance, past and final exam scores, gender, parental education, internet access and extracurricular activities, followed by preprocessing, model training and classification evaluation.
+
1. Project Objective & Dataset +
  • The objective is to develop a Logistic Regression model to classify students as Pass or Fail.
  • The project uses the Student Pass / Fail Dataset.
  • The dataset contains academic performance and demographic attributes such as study hours, attendance, exam scores, gender, parental education, internet access and extracurricular activities.
  • The prediction target is Pass_Fail, where 1 = Pass and 0 = Fail.
2. Input & Target Variables +

Input Variables

  • Study_Hours_per_Week
  • Attendance_Rate
  • Past_Exam_Scores
  • Final_Exam_Score
  • Gender
  • Parental_Education_Level
  • Internet_Access_at_Home
  • Extracurricular_Activities

Target Variable

  • Pass_Fail – Pass = 1, Fail = 0
3. Data Preprocessing & Analysis +
  • Missing values are checked before model development.
  • The unique Student_ID is removed because it is not useful for prediction.
  • Categorical variables are converted and then one-hot encoded.
  • Numerical variables are explored using distributions and correlation analysis.
  • Additional visual analysis includes pair plots and categorical distributions.
4. Logistic Regression Model Development +
  • The processed dataset is separated into input features X and target y.
  • The data is divided into training and testing subsets using an 80:20 split.
  • A Logistic Regression classifier is trained on the training data.
  • The trained model predicts whether a student will Pass or Fail.
5. Model Evaluation +
  • Prediction Accuracy is calculated to measure classification performance.
  • A classification report is displayed for additional performance measures.
  • A confusion matrix is used to examine actual versus predicted classifications.
  • An ROC curve and AUC are used to evaluate the classifier's discrimination performance.
6. Prediction for Student Records +
  • The trained model is used to predict a randomly selected student from the test set.
  • The actual result and predicted result are displayed as Pass or Fail.
  • A second prediction is demonstrated using a manually assumed student record.
  • The assumed record includes study hours, attendance, exam scores and encoded categorical information.
7. Example Prediction & Insights +
  • The project demonstrates how academic and demographic variables can be used for pass/fail classification.
  • The model output can be interpreted as a predicted Pass or Fail result.
  • The project can help illustrate how machine learning may be applied to student performance data.

PROJECT 4
Comparative Study of Optimization and Regularization Techniques in Deep Learning
This project uses the Fashion-MNIST dataset and a Multilayer Perceptron (MLP) to study how different optimization and regularization techniques affect neural network training. Six optimizers are compared using training-loss convergence, while five regularization techniques are analyzed using a common training setup. The project provides visual comparisons of learning behaviour across techniques.
+
1. Project Objective & Dataset +
  • The project uses the Fashion-MNIST dataset for neural-network training.
  • The objective is to compare different optimization techniques and regularization techniques.
  • The dataset contains 28×28 grayscale clothing images represented by 784 pixel values.
  • The ten Fashion-MNIST classes are used for multiclass classification.
2. Data Preparation & MLP Model +
  • The training and testing CSV files are loaded using Pandas.
  • Pixel values are normalized to the range [0, 1].
  • The flattened 784-pixel input is used for an MLP.
  • The common MLP architecture is: 784 → Dense(128, ReLU) → Dense(64, ReLU) → Dense(10, Softmax).
  • Representative images and class distribution are also visualized.
3. Optimization Techniques Comparison +

The project compares the following six optimization techniques:

  • SGD – Stochastic Gradient Descent
  • AdaGrad
  • AdaDelta
  • RMSprop
  • NAG – Nesterov Accelerated Gradient
  • Adam

Each optimizer is used with the common MLP and its epoch-wise training loss is recorded. A consolidated table and comparison graph are then generated.

4. Regularization Techniques Comparison +

The project compares the following five regularization techniques:

  • L1 Regularization
  • L2 Regularization
  • Dropout
  • Batch Normalization
  • Early Stopping

The techniques are trained using the same general SGD-based setup for comparison, and their epoch-wise losses are combined into one comparison table and graph.

5. Loss Convergence & Visualization +
  • Training loss is recorded after each epoch.
  • Individual epoch-vs-loss graphs are generated for each optimizer.
  • The regularization techniques are compared in a single loss-convergence plot.
  • All six optimization methods are compared in a single optimizer-loss plot.
  • These visualizations help compare convergence behaviour across techniques.

PROJECT 5
Student GPA Prediction using Linear Regression
This project predicts future semester GPA of engineering students using historical academic performance data. Separate Linear Regression models are developed for Regular and Lateral students to predict 5th to 8th semester GPAs. The project evaluates each model using R², compares actual and predicted GPA for a selected student record, and also provides editable inputs for further prediction.
+
1. Project Objective & Dataset +
  • The objective is to develop a predictive system for semester-wise GPA forecasting using historical academic data.
  • The project distinguishes between Regular and Lateral students.
  • Separate Linear Regression models are trained for the 5th, 6th, 7th and 8th semester GPA predictions.
  • The project uses the customized Excel dataset student GPA data bank.xlsx.
2. Input & Target Variables +

Input Variables

  • SSC / 10th Grade GPA
  • Intermediate / 12th Grade GPA
  • 1st to 4th Semester GPAs for Regular students
  • 3rd and 4th Semester GPAs for Lateral students
  • Student type – Regular or Lateral

Target Variables

  • 5th Semester GPA
  • 6th Semester GPA
  • 7th Semester GPA
  • 8th Semester GPA
3. Data Preparation & Student Type Identification +
  • Duplicate records are removed.
  • Zero values in semester GPA columns are treated as missing values.
  • A student is classified as Lateral when both 1st and 2nd semester GPAs are missing.
  • All other students are classified as Regular.
  • Semester columns are automatically detected and ordered from 1st to 8th semester.
4. Linear Regression Model Development +
  • Separate feature sets are used for Regular and Lateral students.
  • Independent Linear Regression models are trained for each target semester.
  • The training data is divided into training and testing subsets using an 80:20 split.
  • Each model predicts the GPA of its corresponding future semester.
5. Model Evaluation +
  • Each Regular and Lateral model is evaluated using the R² score.
  • The R² values are displayed separately for 5th, 6th, 7th and 8th semester predictions.
  • This allows the performance of each semester-specific model to be examined independently.
6. Prediction for a Selected Student Record +
  • A selected dataset record can be used for prediction.
  • Missing input features can be replaced with a user-defined fill value.
  • The program predicts the 5th to 8th semester GPAs using the appropriate Regular or Lateral models.
  • When actual GPA values are available, the program displays the actual GPA, predicted GPA and absolute error.
7. Static Input Prediction +
  • Editable example inputs are provided for a Regular student.
  • Editable example inputs are also provided for a Lateral student.
  • The trained models use these values to predict GPAs for the 5th to 8th semesters.
  • This allows users to try different academic histories without modifying the training data.
